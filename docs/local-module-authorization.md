# 本地受保护模块与云端授权

正式受保护模块可以随安装包交付到现有模块目录，运行时仍向云端验证账号、服务器身份、模块授权和发行批次，并取得解密密钥。持有文件不代表已经获得使用权。

自研明文 JAR 和 Debug 保留原有加载方式。正式加密构件使用现有内存模块加载及 Native 验签、解密路径，不改为普通 JAR 明文加载。

## 服主配置

在宿主 `config.yml` 中选择文件来源：

```yaml
cloud:
  qq: "123456789"
  apiKey: "你的验证密匙"
  server-code: ""
  module-source: local
```

| 字段值 | 文件来源 | 授权与解密 |
| --- | --- | --- |
| `cloud`（默认） | 沿用云端下载 | 仍须有效许可证和运行租约 |
| `local` | 现有 `modules/<模块ID>.axb` | 仍须在线验证和取钥；缺文件时不回退下载 |

例如 Market 文件放在 `plugins/ArcartX-Suite/modules/market.axb`。普通本地 `.jar` 的安装方式保持不变。

1. 维护者向指定云端账号发放相应模块许可证。免费模块仍按平台原有免费规则发放；需要仅指定账号使用的模块，应按受限许可证管理。
2. 使用该账号的验证密匙绑定服务器，再在账号页面为该服务器装备模块；已有“一份许可证对应一个装备席位”的规则继续生效。
3. 安装与宿主相同发行批次的受保护模块文件。
4. 启动或同步模块。宿主核对文件摘要、批次及云端返回的发行签名，再使用 Native 解密。

常规发布使用云端已激活的 Suite 批次。客户水印包使用已登记的本地发行批次，取钥时同时核对账号、模块、摘要和后端的装备授权。客户安装包的宿主会自动从本地读取模块。更新时替换同一次导出的宿主和模块。发放席位、正式制包及登记操作见 [模块水印与查验](module-watermarks.md)。

## 安装身份与运行租约

签发或续租还会核对账号当前 apiKey。轮换验证密匙后，旧目录中的旧密匙不能继续续租；应更新合法实例的配置。故障期间备云以已同步状态为准，变更传播受接管宽限限制。

安装密钥对继续保存在 `.cloud-keypair` 中。每次宿主进程启动时，另生成一对只保存在内存的启动密钥。绑定请求须证明安装私钥的持有；取钥请求还须证明当前启动私钥的持有。

正常连接主云时，同一服务器身份只保留一个有效启动租约。复制目录不会复制进程内的启动私钥，不能直接冒用原进程的租约。机器指纹用于辅助诊断，不再自动把旧服务器许可证转交给一个不同公钥。

丢失安装密钥后会产生新的服务器身份，需要在授权账号中重新装备或转移许可证。保留原密钥的正常目录迁移及 IP 变化仍可复用安装身份。

主云侧 `RUNTIME_LEASE_TTL_SECONDS` 可设为 180～1800 秒，默认 1800。宿主约每两分钟续签，并使用单调时钟执行各模块期限。

- 网络暂时失败时，已有签名租约在原期限内继续有效。
- 既有容灾模式生效后，备云可以在固定故障窗口内签发启动租约，支持新启动和接管；备云租约单次最多三分钟。
- 备云 `RUNTIME_FAILOVER_GRACE_SECONDS` 可设 180～1800，默认 1800。窗口从本次故障首次失败或管理员有限接管的开始时间计算，不随重复探测延长。窗口耗尽后，需恢复主云或由管理员确认后重新设置有限接管。
- 主备运行表独立，故障期间可能有短时并发限制及撤销传播滞后。主云恢复时，有效备云签名租约可作为一次性交接凭据；客户端自报 force 字段无效。
- 许可证自身更早到期时，按模块单独停用。授权或租约结束后，停止相关受保护模块及依赖它的模块。
- 正常停机会向签发方主动释放租约；旧请求不能重新占用已释放的启动身份。异常退出时，可能需要等待原期限结束。

更长宽限提高故障时的可用性，也增加异常退出等待和撤销传播窗口。租约不是永久离线授权，不声称在两套独立数据库网络分区时仍有全局强一致的单实例限制。

## 配套升级

此协议需要宿主、主云和备云配套升级：

- 主云执行 `0022_runtime_leases.sql`。
- 备云执行 `0013_runtime_proof_replays.sql`。
- 客户水印包还需要主云 `0023_module_variants.sql` 和 `0024_module_variant_replication_status.sql`、备云 `0014_module_variants.sql`，以及一致的登记密钥配置。
- 两套云端保持原有发行公钥、签名密钥及模块密钥封装配置一致；不通过配置公钥关闭正式构件的 Native 校验。
- 旧客户端不含启动证明，不能通过新取钥协议。应在维护窗口协调升级，不增加“旧协议放行”绕过开关。
- 无许可证归属的历史装备记录、已撤销授权或到期许可证需要由账号侧重新核对，不能用本地模块开关补授权。

这些数据库表只保存临时运行归属和请求去重数据，不作为账号许可证记录同步到另一套云端。主云数据库恢复或重置这类表时，须考虑仍在有效期内的已签发租约。

纯本地软件不能保证授权人无法主动修改宿主、提取已经下发的密钥或分享明文代码。启动证明与租约用于限制正常协议下的复制和多开；水印用于追溯，见 [模块水印](module-watermarks.md)。
