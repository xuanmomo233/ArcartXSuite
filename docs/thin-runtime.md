# 小型宿主与按需运行库

Suite 的 Windows x86_64 和 Linux x86_64 发行包采用小型主 JAR 与按需下载的公共运行库。首次使用缺失的运行库需要联网；已经校验通过的缓存可在后续启动时复用。启用新功能时，如果它依赖尚未缓存的库，仍需要联网。

主 JAR 保留全部 Suite 自研代码、公开 API、认证独立网关，以及对应平台的加密原生保护库。Gson 留在主包，保证独立认证网关仍能以单 JAR 的 classpath 启动；XZ 留在主包，保证原生保护层在下载任何代码前即可启动。

外置库包括 MySQL JDBC、SQLite JDBC（含对应平台的 SQLite 原生资源）、Jedis、Commons Pool、HikariCP、Pinyin4j、公开的 Bouncy Castle Argon2 子集、Java-WebSocket 和 JSON。它们都是公开依赖。ProGuard 是构建工具，不会作为运行库分发；自研的混淆后核心与原生保护实现不会进入公开运行库。

## 加载与保护

1. 原生保护层完成现有的初始化、明文引导类校验与加密类完整性校验。
2. 清单 SHA-256 固定写入受原生明文类校验保护的引导类，防止跨宿主替换旧的有效清单。再使用原生内嵌的 Ed25519 公钥验证清单签名，消息为 `SHA-256("AXS-RUNTIME-1\0" + 清单原始字节)`，不接受服务端提供的新公钥。
3. 每个库固定 SHA-256、大小和允许拥有的包。首次访问该库的类或资源时，加载器先校验本地缓存，再依次尝试主云和 FlareCloud 的 HTTPS 地址。拒绝 HTTP 重定向，限制连接、读取时间和下载大小。
4. 下载先写临时文件，通过完整哈希与大小校验后才移入缓存并加入类路径。缓存位于主 JAR 同级的 `ArcartX-Suite/runtime-libraries/<SHA-256>.jar`，只有公开第三方库。
5. 损坏缓存、无效签名或下载失败会阻止相关运行库加载，不回退使用服务器或其他插件里未经固定的同名包。关闭宿主时先等待业务资源退休，再关闭运行库加载器和 MySQL 清理线程。

签名保障来源与完整性，不为第三方公开库提供保密性。自研代码继续使用现有混淆、逐类加密和原生保护链。拥有服务器进程控制权的人仍可能提取运行时数据，不能承诺绝对防提取或防破解。

## 构建与发布

`shadowJar` 是内部 fat 中间产物，写入 `packaging/`。`thinCoreJar` 将公共依赖拆入 `runtime-libraries/`，输出 `libs/*-unobf*.jar`。生产混淆、字符串处理和逐类加密均接在小型主包之后。

生产构建用 `AXS_RUNTIME_SIGNING_KEY_FILE` 指向 CI 临时生成的 Ed25519 PKCS#8 私钥。私钥不进入产物，签名使用与原生公钥一致的现有签名密钥。CI 的 `verify-runtime.py` 检查最终主包签名、全部运行库哈希、包归属和原生保护库留存。

运行库通过带 CI 令牌的 `/v1/ci/runtime-libraries/:sha256` 上传，公开地址是 `/v1/runtime-libraries/:sha256.jar`。云端拒收 Suite 类、`ENCRYPTED/`、保护层 `native/` 和密钥路径。内容地址不可变，响应可长期缓存。

CI 先向主云及 FlareCloud 上传运行库，再暂存同批宿主和模块。两端暂存完成后，激活步骤按发布清单一起设置宿主与模块的当前版本。FlareCloud 在待机状态也支持经 CI 鉴权的暂存及激活，并提供运行库的公开下载。

向云端暂存前，CI 会为本次工作流保存原始产物及加密清单。重跑发布作业时，已有激活清单便续办激活，否则按已保存的产物续办暂存。重新暂存前校验产物哈希，模块密钥只保存在加密清单中。

生产 CI 依赖两端云服务的运行库上传、宿主与模块暂存及发布激活接口。宿主只加载签名清单中固定哈希的运行库。运行库保留供仍引用它们的宿主使用。

## 开发验证

`buildDev` 生成未混淆的小型主包与公开运行库目录。运行未签名开发包时，在 JVM 参数中显式设置 `-Daxs.runtime.directory=<该构建的 runtime-libraries 绝对路径>`，此模式只读取本地文件并校验哈希。生产加密包拒绝该开关绕过签名或联网校验。

宿主测试覆盖真实的分包类身份、SQLite JNI 查询、所有运行库的类加载，以及签名消息、缓存损坏、镜像失败和重定向拒绝。生产加密、Native 自检和真实 Minecraft 服务端启动仍须以相应 CI 与实机结果为准。
