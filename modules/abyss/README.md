# Abyss 设计、保存与 UI 修复说明

## 可配置结算与示例玩法

每个副本在 `config.yml` 配置结算策略，战斗时间限制在通关/失败后停止。

```yaml
settlement:
  exit-mode: COUNTDOWN             # IMMEDIATE / COUNTDOWN / MANUAL
  exit-delay-seconds: 60
  show-stats: true                 # 同时遵循全局 statistics.auto-show
  show-stats-after-exit: false     # 倒计时/主动离开后是否再打开面板
  manual-timeout-seconds: 0        # MANUAL 的可选上限；0=等待所有玩家主动离开
  protect-players: true
  revive-players: true
  script-timeout-seconds: 30       # 全部离开后，等待结算/退出脚本收尾的上限
  failure:
    exit-mode: COUNTDOWN
    exit-delay-seconds: 15
    show-stats: true
```

- `IMMEDIATE`：下一次安全调度点撤出，传送完成后显示结算；自然掉落物没有额外拾取时间。
- `COUNTDOWN`：在副本内显示结算和独立退出倒计时；可关闭面板继续拾取，也可提前离开。
- `MANUAL`：等待玩家点击“离开副本”或 `/abyss leave`；有人停留时不被普通实例年龄看守强制清理。
  服主可用 `manual-timeout-seconds` 设置资源占用上限，管理员仍可取消实例。

结算面板提供“继续拾取 / 领取奖励 / 离开副本”，显示耗时、评级和队员统计。
退出后面板使用冻结数据，`/abyss stats` 可在本次登录内重看最近结果（显示后保留10分钟）。
关闭面板不会离开副本；结算中退出传送被拒绝时保留实例关系并允许重试。
标准 `exit_dungeon` 在完成/失败脚本中服从结算策略；明确强制退出使用 `force_exit_dungeon` 或管理命令。
结算参与者在脚本创建时冻结，退出/掉线及 `run_script` 子脚本不丢失奖励目标。
全部玩家离开后，世界可以短暂保留用于结算脚本收尾，已完成的脚本及时注销。
外部指令的任意副作用无法自动回滚；商店在尚无成功动作时失败会退回金币，部分执行会明确提示并记录日志。

`example` 采用90秒拾取窗口，取消原完成脚本中的固定退出；`procgen` 采用60秒，
补齐初始化、基础通关奖励、队伍金币、可用商店和休整恢复。旅队商人使用无原版交易界面的实体。

## 2026-10-31 AXS API 与状态安全修复

奖励通过公开 `PendingRewardService.savePendingBatchConfirmed` 整批确认持久化，
由宿主统一认领、补发并交给 `ItemRewardDispatcher`；宝箱仅在确认后消耗领取资格。
宿主用永久操作收据拒绝冲突重放，数据库故障时使用宿主 `pending-reward-outbox/` 恢复日志；
上线或主动补发时导入恢复日志。失败记录保留重试，物品生成、匹配、货币、属性均沿用宿主 API。
新增接口为兼容默认实现；旧宿主不具备确认能力时保持领取关闭，因此本体和模块须使用同一轮 CI 更新。

## 副本作者的使用流程

1. 使用 `/axs abyss design <副本ID>` 进入冻结的设计实例。请留出背包空格，标记杖不会覆盖原物品。
2. 在节点中添加对象，用标记杖定位。房内怪组坐标自动相对房间原点保存；刷怪点落在所点方块上方。
3. 怪物、宝箱选项、奖励权重、增益选项及门盒支持 JSON 对象行，例如：
   `{"mob-id":"vanilla:zombie","location":"5,65,5","amount":3,"level":1}`。
   新建宝箱同时创建对应点击交互；刷怪点以有效的原版僵尸为默认值。
4. “完整配置文件”提供楼层链、房间、阶段、商店、脚本和随机生成参数等 YAML 行编辑；保留原缩进。
   行列表每页最多 12 行，修改、删除使用完整文件中的真实行号。
   同一文件的“对象编辑”和“完整文件编辑”存在冲突时拒绝覆盖，请先分别保存。
   清空可选配置文件的全部行会删除该文件，例如清空 procgen.yml 可关闭随机生成。
5. “保存配置”只保存定义。“配置+建筑”会短暂传送到安全等候位置，卸载设计世界后保存，
   完成后回到设计位置。普通、VOID、schematic 来源均保存为该副本独立的 world/ 快照；
   快照不重复执行生成地形的 world_init 段。
6. 随机副本使用“保存当前构件”：站在房间内部保存，几何会还原到原始旋转方向，
   并更新同名共享房间构件。走廊不属于房间；不同房间请分别保存。
   引擎自动挖出的门洞不会固化为下次随机布局的漏洞。
7. 保存进行中禁止编辑、重复保存和退出。失败保留会话草稿，文件变更会进行冲突检测。
   成功覆盖前的 YAML 位于副本目录 .design-backups/，世界旧版本位于 world.backup-*。
   随机构件的旧文件也保存在构件目录 .design-backups/。
   保存失败或结束有未保存配置的会话时，会另存可读的 .design-drafts/ 恢复副本；它不会覆盖正式定义。
8. 删除对象和放弃未保存编辑均需要在 10 秒内再次点击确认。
   重命名会迁移已支持的 YAML 引用、脚本动作和阶段条件；仍被引用的对象不能直接删除。

floors 的 region 模式支持实例内设计。包含 floors/pool 随机 schematic 楼层的模板仍在入口明确拒绝实例内设计，
应先编辑原房间资源；本次没有将其伪装成可保存的普通世界。
区域构件只存方块状态，不存箱子物品等方块实体 NBT；奖励通过副本宝箱定义配置。

## P1 修复范围

- 标记杖只使用空背包格，退出和掉线收回标记杖。
- 保存校验、文件基线冲突检测、分组暂存、原文件备份与写入失败回滚；失败不重置编辑状态。
- 世界文件在安全卸载后复制并替换，后台复制完成前不会重载模板或报告成功。
  实例销毁等待其世界写入结束，避免边复制边删除源目录。
- 同一模板只允许一个设计会话，避免编辑快照互相覆盖。
- 新对象使用独立的持久化 ID 分配，保存前再检测重复地址。
- 房间重命名迁移楼层引用与子怪组路径，怪组、交互、奖励等迁移受支持的动作和引用。
- snake_case 别名读入编辑快照后归一；追加、删除脚本不丢原内容、不复活旧别名。
- 组队浏览器、确认页和命令使用同一队长、准备及在线检查。
- 随机地图只连接主链/支线的显式边；Boss 清理后仍核验主线房间。
- 怪物生成全失败时终止副本并提示配置错误，空怪组正常完成，避免永久锁房。
- 通关、失败和退出脚本允许在结算状态执行，等待和自定义子脚本保留结算上下文。
  普通玩法脚本不会在副本结束后继续；结算参与者在执行撤出脚本前完成快照。
- 设计实例始终与玩法实例区分，不产生通关记录，不占玩家实例配额或预热世界。
- 自定义门洞通过转折走廊连通；方向全名与偶数宽度一致处理。

## 全部内置 UI 核验表

服务器 ArcartX-Suite/ui 同样有缺陷，不能视为正确样板。上一轮复用的布局已再次独立检查。
本轮以官方控件规范、项目实现和数据包字段为依据；其它模块和服务器文件仅作对照，
没有覆盖服务器里的任何 UI。现有 UI 已在修改前备份到模块 build/ui-backups/。

服务器文件中确认的共性问题包括：动态堆叠列表没有设置容量，超过默认 64 条时会移除早期控件；
宝箱网格使用 spaceBetween、构件目录使用 hSpace/vSpace，均不符合 HGrid 的间距属性；
编辑器和队伍界面的部分 36 号输入字体不小于输入框高度，按钮和说明文字也没有足够的布局空间。
项目修复采用固定的足够大列表容量，避免刷新变少时自动缩容先删掉模板；生成行仍按实际数据清理。

本轮还统一调整了字号层级，为长名称和多行文字设置边界与行距，避免与相邻按钮、条件和列互相覆盖。
预览文字在其范围内裁剪；原始配置值与待编辑脚本保持完整，编辑框支持真实值预填。
队聊在服务端按中英文宽度分行并保留格式与完整内容，界面不再截断长消息。

## 2026-10-31 实际客户端故障复核

客户端 `crash-2026-10-31_12.36.05-client.txt` 记录了 Rendering screen 的 StackOverflowError。
崩溃前最新日志累计出现 3387 次 GameLayerRenderEvent 处理失败；这不能被“UI 已注册”或模拟测试通过替代。

核对该客户端 ArcartX 2.10.100 的实际命中检测实现后，确认 `limitControl: self` 会递归调用自身。
已将全部 43 处此类裁剪改为独立 Canvas 承载边界、内部 Text 引用父 Canvas；
保留原控件的位置、可见性和尺寸，并修正包装后 entry 的父级路径。
Java 资源合同测试和 UI 脚本检查均禁止自指裁剪，避免同类崩溃再次进入构建。

另修正首包发送失败仍标记 ready 的问题：发送失败保留后续更新队列并最多重试三次，
超过次数关闭界面并提示重开；旧代次和已关闭界面的重试仍会被取消。
这里确认的是服务端发送结果，不将其等同于客户端已完成渲染。

修复版 Jar 和全部 14 份 UI 已同步到本地服务器；运行中覆盖 Jar 曾产生旧 ZIP 句柄缓存错误，
本轮通过正常重启加载新构建，后续部署不能用原地覆盖运行中 Jar 来替代安全卸载或重启。
随后使用已进服客户端的原生接口完成下面的实机复核；画面来自游戏 framebuffer，
数据包在真实服务端处理，控件动作在真实 ArcartX 页面上下文执行。
